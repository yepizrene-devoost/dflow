# agent-install-followups

The two follow-ups the #34 review cycle left behind: a real file-mode bug in the
skill installer, and a changelog-curation gap.

## Issues

Closes #35 (`fix(install): preserve mode on skill file overwrite`)
Closes #36 (`chore(agents): DisplayName removed from Agent struct in #34`)

Branch: `bugfix/agent-install-followups` (base: `develop`)

## Goal

Stop `dflow agent --install` from silently widening the permission bits of a
hand-restricted `SKILL.md`, and give the release curator a rule that makes an
accidental removal of a public `pkg/*` symbol visible in the next changelog
instead of depending on someone remembering this one.

## Design decisions (resolved 2026-09-25)

- **#35 — reuse the pattern that already exists.** `writeInstructionFile`
  (`pkg/agent/reference.go:152`) already stats the target and hands
  `writeFileAtomic` the previous `Mode().Perm()`, falling back to `0644` only
  when the file does not exist. `InstallSkill` does the same job on a different
  artifact and does not. The fix is to make the two agree, not to invent a third
  rule.
- **#36 — the note cannot live in `CHANGELOG.draft.md`.** That file is gitignored
  and regenerated by `make changelog` (git-cliff); the durable artifact of the
  release process is the curation step in `RELEASING.md`. The removal of
  `Agent.DisplayName` is the symptom; the cause is that nothing in the runbook
  tells a curator to look for an API removal at all, because `dflow` ships as a
  CLI and its `pkg/*` surface is invisible in release notes unless the curator
  writes it. So the fix is the general rule, applied once, rather than a single
  line about one field.
- **No `## Unreleased` section in `CHANGELOG.md`.** It would add a state the
  release runbook does not know about, and `make release` validates the newest
  `## 📦` section against the tag being published.

      Evidence: RED on the pre-fix source —
      `install_test.go:347: .../SKILL.md mode = 0644, want 0600`;
      GREEN after it, with `TestInstallSkillCreatesAbsentFile` still pinning the
      0644 create path and `gofmt -l pkg/agent/` silent. New pin added as
      "Rule 4"; the rules that followed were renumbered 4→5, 5→6, 6→7 to keep the
      file's sequential convention. Both mode pins (the new Rule 4 and the
      pre-existing Rule 2) are skipped on Windows, matching
      `TestEnsureInstructionReferencePreservesExistingFileMode` and the inode pin
      in this same file: `os.Stat` on Windows reports 0666/0444, so a 0600
      assertion could never hold there and Rule 2 was already failing that rule
      silently for any contributor testing on Windows.

## Out of scope

- Changing `writeFileAtomic`'s signature or its mode semantics — it applies the
  mode it is handed, which is what both callers want.
- A `--force` concept for the skill file: a stale `SKILL.md` is dflow's own
  artifact and is rewritten without asking, by design (rule 3).
- Making `pkg/agent` a documented, versioned public API.
